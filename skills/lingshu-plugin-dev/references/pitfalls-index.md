# 踩坑速查索引（结论先行）

> 归属：`lingshu-plugin-dev` 技能的踩坑**结论索引**；全文（症状 / 原因 / 修复 / 真实案例）在同目录 `pitfalls.md`，按标题搜。
>
> **用法**：开发前按主题扫一遍，命中后到 `pitfalls.md` 搜同一关键词读全文；新增条目先查本文件与 `pitfalls.md` 去重（阶段 5），重复则合并。宿主侧坑见 devconsole/runtime docs，跨侧互引见 `pitfalls.md`「跨侧问题速查」。

## 契约类

**标签索引页也消费 `Listing.filters`（组合串走 `TagContext.category`；`TagContext.sort` 已退役，勿回退宿主硬编码排序行）** / **索引页「类型开关」是换页不是参数（`type` 必须拦在 URL 构造处，漏拦静默返回未筛选结果；A-Z 走服务端 `?section=A` 别做客户端过滤）** / link-target 内跳（旧契约忽略 target，宿主已扩展）/ tags-url 构造约定 / description 与 manifest 一致（**改任一侧必当次同步另一侧，先判哪边是事实真相**）/ url 通道目录页 filters 不受 CLI 强验（**声明前手工实测该页真消费参数**，详见 pitfalls.md）/ labelId 在线验证（fixture 会过期）/ 懒解析 video 块 poster 与顶层 coverUrl 必填（否则观看历史无封面）/ getExplore 裸数组与 viewMore 对象（勿包 { sections } 信封、勿传裸 URL 字符串）/ **详情推荐块块级 viewMore（与分区 viewMore 同型；无对应列表页就不写、落地页 url 必是真实页——**没有独立列表页时它就是承载页本身**（KVS 相关推荐落 `url` = 详情页，同一串 url 既是抓取通道也是落地页的「网站原页」，勿隐藏勿改指），`related` 这类通道标记进 category 而非合成 url，详见 data-model.md「块级『更多』入口」）** / 详情禁内联阅读图一律走 chapter+fetchReadingPage（单话站单条目指向自身）/ 阅读页 `pages` 必须取**原图链**（`a[href]`/查看器地址）而非 `img` 缩略图（**取错不报错、只是投糊图**，以「页数 == 站点声明张数」兜底；以上两条详见 data-model.md）/ **详情 `gallery` 同规矩**（该组图没有阅读页通道时必须给原图链——宿主全屏预览复用同一 URL，给缩略图 = 点开还是糊的）/ **封面缺失用站点自带的占位图**（站点 `.no-thumb`/`.no-image` 的 `background` url，别留空——iOS 空 URL 是**常驻 spinner**、别自造；**⚠ 该资源是 SVG 时 iOS 走自绘子集**（0.1.29 起可用；站点有位图版本仍优先位图，子集外特性会落失败态），DevConsole 正常，详见 pitfalls.md）/ **列表要「看见」时间/数量必须进角标**（`publishTime`/`metadata.itemCount` 都只是数据字段，宿主瀑布流卡不渲染它们——**条数用 `{value, format:'count'}` + `play` 图标，别用 `eye`（那是播放量）**，详见 data-model.md：站点给**绝对日期**才写 `{value, format:'relative'}`，站点原文本来就是**相对文案**（`2 days ago`）就**只换词直给中文串**（`'2天前'`/`'1周前'`/`'12个月前'`）——**别把相对文案换算成时间戳**，宿主 `publishTime` 走**绝对**时间格式化，会渲染成凭空的「2026年10月9日 00:00」，详见 data-model.md / pitfalls.md）/ 详情信息能收尽收（分类作者日期页数热度留言收藏标签简介封面推荐，有则收录无则省略不伪造，详见 data-model.md）；

## 解析类

**同一个 URL 两副面孔的「页面即接口」站——判别开关是请求头 `X-Requested-With` 而不是请求方法**（带该头回 JSON 信封、不带回 SSR 骨架；信封里 `template` 又可能是**HTML 片段串**，用 cheerio 解属性别用正则；分页 `hasMore` 主判据用 `current_page < total_pages`，**末页 `next` 可能回指自身**；多跳动作离线必须用目录式 fixture，详见 pitfalls.md 与 runtime/docs/fixture-modes.md） / **详情元数据靠 JSON-LD 而站点 JSON-LD 畸形（尾部多一个 `}`）→ 按大括号配平截取第一个完整对象**（模板 helper `extractBalancedJson`；必须跳过字符串内括号与转义，与 flight payload 的配平规则不是一回事；解析失败要留痕，别静默丢一半元数据，详见 pitfalls.md）

**服务端对无效参数可能「宽松兜底」——有数据 ≠ 参数有效**（未知 type 不报错、返回满页默认内容；选项真实性用「兜底指纹」验：随机无效值取 id 集合作指纹，逐候选比对，相同即无效；条数都是 24 区分不出来。某池为空/两入口同内容都不等于无效，详见 pitfalls.md） / **CryptoJS 传字符串密钥（passphrase）的密文是 OpenSSL 格式**（密文前缀 `U2FsdGVkX1`/`Salted__` + `EVP_BytesToKey-MD5` 派生 key/iv，非裸 CBC；插件用 `$lib.CryptoJS.AES.decrypt(密文, 密钥)` 直解、**不用手搓**，Node 原生复刻只在分析期脱浏览器批量验证时用——对象 key `{key,iv}` 才是裸 CBC，先看前端调用形式，详见 pitfalls.md） / 首屏 HTML 与翻页 AJAX 接口分离的站 cursor 必须拼翻页锚接口（拼首屏 URL 等于反复要首屏；到底认 fail/cursor=0 双标记，详见 pitfalls.md） / **动图封面别信后缀与 Content-Type（按字节魔数判；iOS 只显首帧、不失败，http 图床能升 https 就升，详见 pitfalls.md）** / 渲染后 DOM-fixture 掩盖运行时接口 / 同站多播放器形态（新老视频出流双栈，渲染后 blob 反向掩盖，看原始 HTML，详见 video-playback.md）/ 沙箱无 URL 全局 / 已返回对象勿二次 JSON.parse / 写侧以 code 判定 / SSL 证书失败 / 父容器 text 相邻粘连 / 多行简介换行丢失（逐行清洗 + `<br>` 先转 `\n`）/ 详情缺尾斜杠回首页站 fetchDetail 入口补斜杠（iOS 历史库去尾斜杠，manga_site_e）/ lazy-load 双态（**SSR 真值在 data-original、渲染后该属性被库删掉而 src 才成真值**；取图 `data-original→data-webp→data-src→src` 并跳 `data:`，详见 pitfalls.md）/ 页面通道形态判定先剥协议+域名（`context.url` 是完整地址，只对 path 判）、且**页码段与详情 ID 段同为数字时按段数/slug 分类**（勿只看前缀，详见 pitfalls.md） / **详情恒报「不存在/已下架」而列表正常 → 先查 id 提取正则**（`\d+` 只吃数字前缀，hex/字母 id 被静默截断：`5887fcd476654036`→`5887`，请求照样发出；id 一律按路径段全取，构造侧同理，详见 pitfalls.md；页签形态与地址两条纪律见 listings.md 规则 12/15）/ **SPA 的 `origin` 地址要按「这地址实际发什么请求」验，别按内部路由枚举名拼**（枚举名 `community` 的路由是 `#/post`、`#/community` 是死路由（零请求、页面空白不报错）；分组归属同样会照名字猜错——静态找页面注册表/页面类读的配置字段 + 在已加载页里改 `location.hash` 逐跳对齐接口，别用整页重载，详见 pitfalls.md；**且带参内部路由不是地址**——`A.b6(path,params)` 是 push 路由、参数不进 URL，`#/home/movie/detailH?id=`、`#/home/movie/tagDetail?id=`、`#/home/movie/blockDetail?id=`、`#/profile?homeId=` 四个实测全无页面（零请求或回退首页）：参数化列表页一律自造稳定标识当地址，见 listings.md 规则 15/18）/ **子页签参数穷举不出来 ≠ 站点不支持：多半是服务端 navFilter 类接口在下发**（`/post/navFilter {id}.filters` 才是各页签整份参数，现取现用 + 只回退首页签档；页签的 `style` 是布局形态不是参数值，详见 pitfalls.md） / **聚合页分区是异构的：条目映射器按分区自报类型分派**（`style:'20'` 的作者块条目是创作者，用视频映射器会逐条判空、随后整块被 `if (!items.length) return` 静默丢掉——CLI 只少打一个分区号不报错；逐块打 `style/route/条数/首条字段集` 排查，详见 pitfalls.md）/ **端点回「网络异常」≠ 网络问题：缺的多半是站点自己的语义参数**（`/movie/daily` 必需 `label=<YYYY-MM-DD>`，缺参文案与原因无关；搜 dart2js 里端点字面量的 `A.by(...)` 实参表拿参数名、顺调用者拿格式，比试参数快；日期档做成 `type:'text'` 的页级筛选 + 缺省当天 + 格式前置校验，详见 pitfalls.md 与 listings.md 规则 16）/ **筛选参数「看着像」不等于生效：固定三点对照**（无参 total / 有效值 / **无效值必须回 0**，两两不同才算真维度；total 有封顶噪声时改看首几条 id——video_site_h `/search/post` 换 tag_id 时 total 都是 10000 而 id 真的变了，只盯 total 会误判「参数无效」，详见 pitfalls.md） / **服务端下发的 filter 对象不能整份照抄：里面混着页级/广告键**（`position`/`ad_code` 属于页面白名单；`/movie/tagDetail` 会把你传的 position 原样回填进四档 filter（**回填 ≠ 校验**），照抄给 `/search/movie` 直接 0 条——只取「三点对照」验过的内容键，详见 pitfalls.md） / **一页多块时条目与分页都必须带块作用域**（`.pagination`/`.item` 是块内通用类名，`$('.pagination').first()` 会拿到**文档顺序第一组**——页码与 hasMore 静默全错，详见 pitfalls.md）/ 标签分组云分组边界不保证是独立容器（同 ul 内混排多分组，按 li 顺序扫，详见 data-model.md）/ 列表推广卡按 href 形态剔除（详见 pitfalls.md）/ 作者链接取文本最长者（头像 fallback 同 href 干扰，详见 pitfalls.md）/ 卡片三件套（根自带底 + 列容器显式左对齐 + ## 内容类

**「解锁 VIP」需求先判付费墙层级——前端字段驱动 ≠ 服务端鉴权**（改写脚本改的是客户端 UI 层，插件不经过前端；用身份对照实验定层级：身份参数四值——不传/空/真实值/乱码——响应一致即零鉴权，插件**不消费门槛字段**，能出流以接口是否给地址为准，标注走形态。**第二形态：门槛只差「前端自己少传的一个请求参数」（预告档 `&is_trailer=1`）——身份维度照样四值一致，去掉该参数即拿全量，`role/max-duration/join` 一律不读**，详见 pitfalls.md） / 阅读页 prevNext / HLS-403 先查视频调试日志 / 全站CF拦截L3（挑战识别下沉宿主，插件只留直连+解析兜底、CHALLENGE 直抛交宿主验证入口——**插件侧浏览器重抓已退役，**）/ challenge-platform 信标注入正常页（宿主强特征集已剔除，插件用 assertParsed 解析兜底，勿另写否定门）/ 按窗口计数烧声誉（frx 一次拿全、一页一环境，anime_site_a）/ macCMS-show 筛选路由被 CF 拦截 / SSR 懒加载标记勿依赖运行时属性 / packed 解包链路自足 / 分页 query-vs-path 两形态 / 列表 summary 长文本致 iOS 滚动掉帧（视频简介默认不发，留详情页，movie_site_a 动漫，详见 pitfalls.md）。

## 链路类

播放页 encrypt/签名/时效 URL（见 pitfalls.md + `_fixtures/movie_site_c/analysis.md`）。**同站多 API 镜像（v2.a/v2.b/…）要顺序故障转移，别写死一个域名**（判据用「业务数据可解析」而非 HTTP 200——失活镜像常回 200 的错误页；与 movie_site_a「播放线路择优」不同层级：镜像择数据入口、线路择出流地址，详见 pitfalls.md）。**flight 解码必须完整处理 `\uXXXX`（朴素取下一字符静默坏标题，详见 website-analysis.md）** / **不校验 Referer 的 CDN 不声明 `referer`（多写即死链，详见 video-playback.md）** / **站点展示数可能是前端现算假数（角标只认接口字段，详见 pitfalls.md）** / **首屏 SSR 有数不等于无分页（滚屏后重查 net，详见 website-analysis.md）** / **无封面大索引走标签云（详见 listings.md 规则 13）**。

## 站点专题（KVS）

KVS 站搜索：翻页/筛选是 AJAX-only（`?page=` 与 `/search/{q}/{N}/` 均被忽略），必须走 `mode=async&function=get_block` 片段接口；`category_ids=1,5` 逗号是多选并集（`[]=` 形态回 500），`sort_by` 对 `/latest-updates/` 无效（见 pitfalls.md）。

KVS 站会员（`/members/{id}/` 与 `/members/` 同前缀不同形）：`/members/{id}/` 是会员作品页、本身是列表页但**只有 3 条/页**、`/members/{id}/2/` **404**（分页同走 `get_block` + `block_id=list_videos_uploaded_videos`），`/members/` 是「社区」**多区块聚合页**（成员榜 18 条/页 + 新私密视频 12 + 新私密图集 12）→ listings 走 `kind:'explore'` 三分区，成员榜分区的 `viewMore` 落成员榜列表页（`from_members=N` **整页 SSR 可直取**、`?sort_by=` 5 档、`/members/2/` 404）→ 两页**都必须带块作用域**取条目与分页，路径分类把 `{id}` 判在前（见 pitfalls.md / `_fixtures/kvs_site_a/analysis.md` §7/§12）。

KVS 站图集（`/albums/`）：与视频**同前缀不同形**——索引/页码页（`/albums/`、`/albums/{N}/`）是列表、带 slug 的 `/albums/{id}/{slug}/` 是详情（路径分类靠 slug 段，勿只看前缀或裸数字 ID）；列表卡 `.list-albums .item`（`.photos` 张数 + `.rating` 百分比），原图在 `.block-album .images a.item[href]`（`img` 只是缩略图）；path 分页且 `?sort_by=` **生效**（档位 `album_viewed` ≠ 视频 `video_viewed`）；整本一次给全（见 pitfalls.md / data-model.md）。

KVS 站私有内容（需登录）：列表 `span.ico-private` → 打 `tags`「需登录」（照常列出，**不许**省略——站点图标只在网页上、不落标签行等于用户白点）；详情 `span.message` → 置顶提示块，且**不许**产出点进去必报错的入口（私有图集原图清单恒空）；阅读页私有必须先于通用分支抛「需登录」，别用「页面结构可能已变化」描述它（见 pitfalls.md）。

KVS 站相关推荐块（`#list_videos_related_videos` / `#list_albums_related_albums`）：详情页首屏只给一屏，**「更多」是 AJAX 锚且 `href="#more"` 不是地址**（只带 `data-block-id` + `data-parameters`）→ 站方没有可跳转的列表页；要「更多」落地的站，落法是块级 `viewMore: {action:'list', url: 本详情页, category:'related=1'}` + `fetchList` 在该标记下走 `get_block&from=N` 片段（**参数名照各自锚抄**：相关块 `from`、会员作品块 `from_videos`，互套会静默取不到条目；`hasMore` 以 `#<blockId>_pagination a` 在不在为准，`.pagination`/`li.next` 在这条通道恒判 false）。`from=1` 与详情页首屏那块**同源**（快照实测完全同序同内容，故列表页首屏接得上；站点该块会随新投稿小幅漂移，属正常 churn）。**凡块渲染了 `li.next > a[data-container-id="<blockId>_pagination"]` 的都算「有列表页」**（末页退化成 `<span>Next</span>` 即停），别只看锚的 `href="#…"` 不是地址就判没有——**漏判 = 把站点能力丢掉**（kvs_site_a 社区页两个私密分区曾因此不给 `viewMore`，v1.9.0 补 `private=videos|albums` 块通道）；给 `viewMore` 时**别漏该块自己的排序档**（同一页各块档位各不相同，抄块头 `<ul id="<blockId>_sort_list">`，见 pitfalls.md）（kvs_site_a 案例，见 data-model.md「块级『更多』入口」）。
